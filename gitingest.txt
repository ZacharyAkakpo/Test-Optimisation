# Optimisation de l'infrastructure technique

Pipeline qui analyse les logs de supervision d'une PME, détecte les anomalies et
propose des actions d'optimisation à Jean, le CTO.

- **Entrée** : [data/rapport.json](data/rapport.json), 500 relevés toutes les 30 min.
- **Sortie** : [output.json](output.json), au format demandé.

## Lancer le projet

```bash
python -m venv .venv
.venv\Scripts\activate          # Linux/macOS : source .venv/bin/activate
pip install -r requirements.txt

python -m infra_optimizer        # lit data/rapport.json, écrit output.json
python -m pytest                 # 10 tests
```

Options : `--input`, `--output`, et `--no-llm` pour n'utiliser que les règles.
Le LLM (Claude) n'est appelé que si `ANTHROPIC_API_KEY` est définie, par exemple
dans un fichier `.env` (voir `.env.example`).

## Architecture

Le pipeline est un graphe LangGraph de 6 étapes qui se partagent un même état :
chaque étape lit ce dont elle a besoin et y ajoute ses résultats.

```mermaid
flowchart LR
    ingest --> analyze --> detect_anomalies --> recommend
    recommend -- clé API --> refine_with_llm --> build_report
    recommend -- sinon --> build_report
```

| Étape | Rôle |
|---|---|
| `ingest` | Lit le JSON, écarte les relevés invalides (ex. CPU à 150 %), trie par date |
| `analyze` | Calcule les indicateurs (latence moyenne, CPU max…) et la disponibilité de chaque service |
| `detect_anomalies` | Compare chaque métrique à ses seuils et chaque service à son objectif de disponibilité |
| `recommend` | Choisit dans le catalogue les recommandations déclenchées par les anomalies |
| `refine_with_llm` | *(optionnel)* Claude priorise et reformule les recommandations |
| `build_report` | Assemble le rapport final |

| Fichier | Contenu |
|---|---|
| [config.py](infra_optimizer/config.py) | Tous les réglages : seuils par métrique, objectif de disponibilité, modèle LLM |
| [playbook.py](infra_optimizer/playbook.py) | Le catalogue des recommandations |
| [models.py](infra_optimizer/models.py) | Format d'un relevé, format du rapport, état du graphe |
| [nodes.py](infra_optimizer/nodes.py) | Les étapes `ingest` → `build_report` (sauf le LLM) |
| [llm.py](infra_optimizer/llm.py) | L'étape LLM |
| [graph.py](infra_optimizer/graph.py) | L'enchaînement des étapes |
| [\_\_main\_\_.py](infra_optimizer/__main__.py) | La ligne de commande |

## Choix techniques

- **Python** : c'est le langage de référence pour la donnée et l'IA. Pour 500 relevés,
  le module standard `statistics` suffit, sans pandas.
- **LangGraph** : il rend les étapes et leur enchaînement explicites, y compris le
  passage optionnel par le LLM. Ajouter une étape se fait en une ligne.
- **Pydantic** : il valide les relevés en entrée, garantit le format du rapport en
  sortie et impose un format de réponse au LLM.
- **Les calculs sont faits par du code, pas par le LLM.** Les chiffres d'un rapport
  doivent être exacts et reproductibles. Le LLM se contente de reformuler et de
  prioriser.
- **Les recommandations sont des données, pas du code.** Le catalogue est une simple
  liste de dictionnaires, facile à relire et à compléter.
- **Le LLM est encadré.**
  - Sa réponse suit un format imposé, vérifié automatiquement.
  - Il ne peut pas modifier les paramètres techniques.
  - En cas d'erreur (réseau, clé, quota, réponse invalide), le rapport est quand
    même produit avec les recommandations du catalogue.
  - Le SDK officiel d'Anthropic est utilisé directement, avec le modèle
    `claude-opus-5-5` par défaut (réglable dans `config.py` ou via `.env`).

## Méthode de détection

- **Métriques.** Chaque métrique a trois seuils dans `config.py` : `low`, `medium`
  et `high`. Dès que `low` est dépassé, c'est une anomalie, et sa sévérité est le
  niveau le plus élevé atteint par le pic. On produit une seule anomalie par
  métrique, plutôt qu'une par relevé.
- **Services.** La disponibilité d'un service est la part des relevés où il est
  `online`. En dessous de 99 %, c'est une anomalie : sévérité `high` si le service
  a été hors ligne, `medium` s'il a seulement été dégradé. On indique aussi le taux
  d'erreur pendant ses incidents, pour mesurer leur impact réel.
- **Récurrence.** Si au moins la moitié des intervalles entre deux incidents ont la
  même durée, la description l'indique (« Récurrent : toutes les 5 h »).

## Choix d'interprétation du format de sortie

- `timestamp` : date de génération du rapport.
- `insights.error_rate` : taux d'erreur moyen. `insights.uptime_seconds` : uptime au dernier relevé.
- `anomalies` :
  - `value` est le pic observé et `threshold` le seuil du niveau de sévérité retenu.
  - Pour un service, `metric` vaut `<service>_availability_pct`, `value` est sa
    disponibilité et `threshold` l'objectif de 99 %.
- `service_status_summary` : chaque service est classé selon son **pire** statut sur
  la période. Au dernier relevé, tout est `online` : se fier uniquement à ce relevé
  masquerait les incidents.

## Ce que révèlent les données

1. **Des pics de charge toutes les 5 h.** CPU jusqu'à 99 %, latence de 384 ms contre
   132 ms habituellement, taux d'erreur de 13 %, et l'API gateway se dégrade.
2. **La base de données est hors ligne toutes les 3h30**, alors que le taux d'erreur
   reste normal (0.020 contre 0.032 en moyenne globale). Il s'agit probablement
   d'une sonde de santé trop sensible ou d'une tâche planifiée, plutôt que d'une
   vraie panne.
3. **Le cache se dégrade toutes les 15 h**, au même rythme que les pics de threads.
4. **Un relevé toutes les 30 min, c'est trop peu** pour mesurer la durée réelle des coupures.

## Modifier le projet

- **Changer un seuil** : modifier la ligne de la métrique dans `config.py`.
- **Ajouter une recommandation** : ajouter un dictionnaire dans `playbook.py`. Ses
  textes peuvent citer des mesures, comme `{cpu_usage_max}` ou `{cache_availability_pct}`.
- **Surveiller une nouvelle métrique** : ajouter le champ dans `LogRecord`
  (`models.py`) et une ligne dans `THRESHOLDS` (`config.py`).
- **Ajouter une étape** : écrire une fonction `def mon_etape(state) -> dict` dans
  `nodes.py`, puis la brancher dans `graph.py`.

## Limites

- Les seuils sont des valeurs courantes, à ajuster avec l'équipe selon ses objectifs.
- Les gains annoncés sont des estimations.
- Les données décrivent un seul serveur. Pour un parc, il faudrait un champ `host`
  et une analyse par machine.

"""Lancement : python -m infra_optimizer [--input data/rapport.json] [--output output.json] [--no-llm]"""

import argparse
import logging
import sys
from pathlib import Path

from dotenv import load_dotenv

from .graph import run_pipeline


def main(argv: list[str] | None = None) -> int:
    parser = argparse.ArgumentParser(prog="python -m infra_optimizer")
    parser.add_argument("--input", default="data/rapport.json", help="fichier de relevés JSON")
    parser.add_argument("--output", default="output.json", help="rapport à produire")
    parser.add_argument("--no-llm", action="store_true", help="n'utiliser que le catalogue de règles")
    args = parser.parse_args(argv)

    load_dotenv()  # lit ANTHROPIC_API_KEY dans un fichier .env s'il existe
    sys.stdout.reconfigure(encoding="utf-8")  # accents corrects dans la console Windows
    logging.basicConfig(level=logging.INFO, format="%(levelname)s %(message)s", stream=sys.stdout)

    try:
        state = run_pipeline(args.input, use_llm=not args.no_llm)
    except (OSError, ValueError) as error:  # fichier absent, JSON invalide, aucun relevé valide
        logging.error(error)
        return 1

    report = state["report"]
    Path(args.output).write_text(report.model_dump_json(indent=2), encoding="utf-8")
    logging.info(
        "%d anomalies, %d recommandations (source : %s) -> %s",
        len(report.anomalies), len(report.recommendations), state["source"], args.output,
    )
    return 0


if __name__ == "__main__":
    sys.exit(main())

"""Le pipeline sous forme de graphe LangGraph :

    ingest -> analyze -> detect_anomalies -> recommend -> (refine_with_llm) -> build_report
"""

import os

from langgraph.graph import END, START, StateGraph

from .llm import refine_with_llm
from .models import State
from .nodes import analyze, build_report, detect_anomalies, ingest, recommend


def llm_or_report(state: State) -> str:
    """Après les règles, on passe par le LLM seulement s'il est activé et qu'une clé API existe."""
    if state.get("use_llm") and os.getenv("ANTHROPIC_API_KEY"):
        return "refine_with_llm"
    return "build_report"


def build_graph():
    graph = StateGraph(State)
    graph.add_sequence([ingest, analyze, detect_anomalies, recommend])
    graph.add_node(refine_with_llm)
    graph.add_node(build_report)

    graph.add_edge(START, "ingest")
    graph.add_conditional_edges("recommend", llm_or_report, ["refine_with_llm", "build_report"])
    graph.add_edge("refine_with_llm", "build_report")
    graph.add_edge("build_report", END)
    return graph.compile()


def run_pipeline(input_path, use_llm: bool = True) -> State:
    return build_graph().invoke({"input_path": str(input_path), "use_llm": use_llm})

En cas de problème, on garde simplement les recommandations du catalogue.
"""

import logging

import anthropic

Pour chacune, réécris `action` (une phrase concrète) et `benefit_estimate` (gain chiffré) en t'appuyant sur
les anomalies : récurrence, services touchés, chiffres mesurés. N'invente aucune mesure. Réponds en français."""


# Format de réponse imposé au modèle (vérifié automatiquement par Pydantic).
class RewrittenRecommendation(BaseModel):
    id: str
    action: str
    benefit_estimate: str


class LLMAnswer(BaseModel):
    recommendations: list[RewrittenRecommendation]


def refine_with_llm(state: State) -> State:
    context = {
        "insights": state["insights"].model_dump(),
        "anomalies": [a.model_dump() for a in state["anomalies"]],
        "recommendations": [r.model_dump() for r in state["recommendations"]],
    }
    try:
        response = anthropic.Anthropic().beta.messages.parse(
            model=LLM_MODEL,
            max_tokens=16000,
            output_config={"effort": LLM_EFFORT},
            # Si le modèle décline la requête, l'API la relance sur un modèle de repli.
            betas=["server-side-fallback-2026-07-01"],
            fallbacks="default",
            system=PROMPT,
            messages=[{"role": "user", "content": json.dumps(context, ensure_ascii=False)}],
            output_format=LLMAnswer,
        )
        answer = response.parsed_output
        if answer is None:
            raise ValueError("réponse vide")
    except (anthropic.APIError, ValueError) as error:  # réseau, clé invalide, quota, réponse non conforme...
        logger.warning("LLM indisponible (%s) : recommandations du catalogue conservées.", error)
        return {"source": "rules"}

    # On applique les nouveaux textes, dans l'ordre choisi par le LLM.
    by_id = {r.id: r for r in state["recommendations"]}
    rewritten = [
        by_id[item.id].model_copy(update={"action": item.action, "benefit_estimate": item.benefit_estimate})
        for item in answer.recommendations
        if item.id in by_id
    ]
    # Filet de sécurité : une recommandation oubliée par le LLM est remise à la fin.
    kept = {r.id for r in rewritten}
    rewritten += [r for r in state["recommendations"] if r.id not in kept]
    return {"recommendations": rewritten, "source": f"llm:{LLM_MODEL}"}

"""Les étapes du pipeline. Chaque nœud reçoit l'état et renvoie les clés qu'il y ajoute."""

import json
import logging
import statistics
from collections import Counter
from datetime import UTC, datetime, timedelta
from itertools import pairwise
from pathlib import Path

from pydantic import ValidationError

from .config import RECURRENCE_MIN_SHARE, SERVICE_SLO_PCT, THRESHOLDS
from .models import (
    Anomaly,
    Insights,
    LogRecord,
    Recommendation,
    Report,
    ServiceStatusSummary,
    State,
)
from .playbook import PLAYBOOK

logger = logging.getLogger(__name__)

# Sévérités, de la plus grave à la moins grave, avec leur libellé dans les descriptions.
SEVERITIES = {"high": "critique", "medium": "majeur", "low": "alerte"}


def ingest(state: State) -> State:
    """1. Lit le fichier JSON et garde les relevés valides, triés par date."""
    data = json.loads(Path(state["input_path"]).read_text(encoding="utf-8"))
    if isinstance(data, dict):  # l'énoncé montre un relevé seul, le fichier fourni une liste
        data = [data]

    records = []
    for index, item in enumerate(data):
        try:
            records.append(LogRecord.model_validate(item))
        except ValidationError:
            logger.warning("Relevé n°%d ignoré : format invalide.", index)
    if not records:
        raise ValueError("Aucun relevé valide dans le fichier.")

    records.sort(key=lambda r: r.timestamp)
    gaps = [b.timestamp - a.timestamp for a, b in pairwise(records)]
    step = statistics.median(gaps) if gaps else timedelta(0)  # intervalle habituel entre deux relevés
    return {"records": records, "step": step}


def analyze(state: State) -> State:
    """2. Calcule les indicateurs globaux et la disponibilité de chaque service."""
    records = state["records"]
    insights = Insights(
        average_latency_ms=round(statistics.mean(r.latency_ms for r in records), 2),
        max_cpu_usage=max(r.cpu_usage for r in records),
        max_memory_usage=max(r.memory_usage for r in records),
        error_rate=round(statistics.mean(r.error_rate for r in records), 4),
        uptime_seconds=records[-1].uptime_seconds,  # uptime au dernier relevé
    )

    availability = {}
    summary = ServiceStatusSummary()
    for service in sorted({name for r in records for name in r.service_status}):
        statuses = [r.service_status[service] for r in records if service in r.service_status]
        availability[service] = round(100 * statuses.count("online") / len(statuses), 1)
        # On classe le service selon son pire statut sur la période, pour ne pas masquer les incidents.
        worst = "offline" if "offline" in statuses else "degraded" if "degraded" in statuses else "online"
        getattr(summary, worst).append(service)

    return {"insights": insights, "availability": availability, "service_summary": summary}


def detect_anomalies(state: State) -> State:
    """3. Compare chaque métrique à ses seuils et chaque service à son objectif de disponibilité."""
    records, step = state["records"], state["step"]
    anomalies = []

    for metric, t in THRESHOLDS.items():
        breaches = [r for r in records if getattr(r, metric) >= t["low"]]
        if not breaches:
            continue
        peak = max(getattr(r, metric) for r in breaches)
        severity = next(s for s in SEVERITIES if peak >= t[s])  # niveau le plus grave atteint
        share = 100 * len(breaches) / len(records)
        description = (
            f"{t['label']} : pic à {fmt(peak, t['unit'])} (seuil {SEVERITIES[severity]} : {fmt(t[severity], t['unit'])}), "
            f"{len(breaches)} relevés au-dessus de {fmt(t['low'], t['unit'])} ({share:.1f} % du temps)."
            + recurrence([r.timestamp for r in breaches], step)
        )
        anomalies.append(Anomaly(metric=metric, value=peak, threshold=t[severity], severity=severity, description=description))

    for service, pct in state["availability"].items():
        if pct >= SERVICE_SLO_PCT:
            continue
        incidents = [r for r in records if r.service_status.get(service, "online") != "online"]
        offline = sum(r.service_status[service] == "offline" for r in incidents)
        error_rate = statistics.mean(r.error_rate for r in incidents)
        description = (
            f"Service {service} : disponible {pct:g} % du temps (objectif {SERVICE_SLO_PCT:g} %), "
            f"{offline} relevés hors ligne et {len(incidents) - offline} dégradés. "
            f"Taux d'erreur moyen pendant ces incidents : {error_rate:.3f} (moyenne globale : {state['insights'].error_rate:.3f})."
            + recurrence([r.timestamp for r in incidents], step)
        )
        anomalies.append(
            Anomaly(
                metric=f"{service}_availability_pct",
                value=pct,
                threshold=SERVICE_SLO_PCT,
                severity="high" if offline else "medium",
                description=description,
            )
        )

    anomalies.sort(key=lambda a: list(SEVERITIES).index(a.severity))  # les plus graves d'abord
    return {"anomalies": anomalies}


def recommend(state: State) -> State:
    """4. Retient dans le catalogue (playbook.py) les recommandations déclenchées par les anomalies."""
    in_anomaly = {a.metric for a in state["anomalies"]}
    values = measured_values(state)

    recommendations = []
    for rec in PLAYBOOK:
        triggered = in_anomaly if rec["when"] == "*" else in_anomaly & set(rec["when"])
        if triggered:
            recommendations.append(
                Recommendation(
                    id=rec["id"],
                    action=rec["action"].format(**values),
                    target=rec["target"],
                    parameters=rec["parameters"],
                    benefit_estimate=rec["benefit_estimate"].format(**values),
                )
            )
    return {"recommendations": recommendations, "source": "rules"}


def build_report(state: State) -> State:
    """6. Assemble le rapport final au format demandé."""
    report = Report(
        timestamp=datetime.now(UTC).isoformat(timespec="seconds").replace("+00:00", "Z"),
        insights=state["insights"],
        anomalies=state["anomalies"],
        recommendations=state["recommendations"],
        service_status_summary=state["service_summary"],
    )
    return {"report": report}


# --- Petites fonctions utilitaires ---


def fmt(value: float, unit: str) -> str:
    """99.0, '%' -> '99 %' ; 0.13, '' -> '0.13'"""
    return f"{value:g} {unit}".strip()


def recurrence(timestamps: list[datetime], step: timedelta) -> str:
    """Renvoie « Récurrent : toutes les X h. » si la plupart des incidents sont espacés de la même durée."""
    gaps = [b - a for a, b in pairwise(timestamps) if b - a > step]  # on ignore les relevés consécutifs
    if len(gaps) < 2:
        return ""
    gap, count = Counter(gaps).most_common(1)[0]
    if count / len(gaps) < RECURRENCE_MIN_SHARE:
        return ""
    return f" Récurrent : toutes les {gap.total_seconds() / 3600:g} h."


def measured_values(state: State) -> dict[str, str]:
    """Valeurs que les textes du catalogue peuvent citer : {cpu_usage_max}, {cache_availability_pct}..."""
    values = {"sampling_minutes": f"{state['step'].total_seconds() / 60:g}"}
    for metric in THRESHOLDS:
        column = [getattr(r, metric) for r in state["records"]]
        values[f"{metric}_max"] = f"{max(column):g}"
        values[f"{metric}_median"] = f"{statistics.median(column):g}"
    for service, pct in state["availability"].items():
        values[f"{service}_availability_pct"] = f"{pct:g}"
    return values
